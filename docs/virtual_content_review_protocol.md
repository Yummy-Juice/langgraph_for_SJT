# PSJT 虚拟内容复审与 Facet 迭代协议

本协议用于候选题开发期的探索性虚拟筛查与内容诊断，不是正式真人信度或效度验证。MTE 专家审题、认知访谈及 COSMIN 相关性、完整性、可理解性等概念用于约束复审证据；虚拟专家和虚拟认知角色不能替代真人 SME 或目标人群访谈。下列指标阈值、测量顺序、局部预算和控制器状态均为本项目操作化，不是 MTE 或 COSMIN 发布的通用标准。

## 指标与判定边界

- 单题决策使用合并所有已配置分数档后重算的总指标。分档指标仅作诊断展示，单档结果不单独触发返修。
- 四项主动单题门槛为：分面内题项总分相关 `CITC ≥ .30`；单题目标 IPIP Hedges' `g ≥ .50`；单题目标 IPIP Spearman `ρs ≥ .40`；单题最小区分差 `Δmin ≥ .30`。记录字段为 `citc_pass`、`target_hedges_g_pass`、`target_ipip_spearman_rho_pass`、`discriminant_delta_min_pass`；四项全部通过才是单题 `qualified`。任一主动门槛不可估计时按未通过处理。
- Profile 目标 `rho_s`、同域 VTS 和跨域 VTS 保留为三项诊断值，不再作为单题门槛。诊断字段必须记录 `threshold=None`、`passes=None`、`filtering_authority=false`；任何显示端不得将 `None` 解释为失败。VTS 按固定三臂中非目标 facet 的最大带符号 rho 计算，不取绝对值；各组、所选 facet、带符号 rho 和 VTS 诊断值仍可保留用于解释。
- 五项 facet 整卷指标为 `Cronbach α`、重测 `ICC`、目标 IPIP `g`、目标 IPIP `rho_s` 和 `Δmin`。后续成功开发轮要求 `α ≥ .70`、`ICC ≥ .70`，且 `g`、`rho_s`、`Δmin` 均相对上一完成轮严格上升，差值 `> 1e-12`。
- 整卷指标属于探索性虚拟开发证据，不是真人信度、效度或测验资格证明。难度、选项使用率及 Profile 指标不替代四项主动单题门槛或五项整卷指标。

## 施测与数据合并

1. 冻结构念材料、目标人群、蓝图、题目槽位、分数档和 facet groups。保持确定性选项顺序平衡、稳定被试 ID、去重和可恢复性；旧版重复作答配置或结果不得静默复用。
2. 首轮基线一次性施测 cohort、IPIP 校标和所有当前题目，按既定整卷测量流程计算五项 facet 指标。首个完整且必需指标可估计的整卷结果直接建立基线；即使 `α` 或 `ICC` 未达到 `.70`，也不因后续成功轮门槛失败而拒绝建立基线。首轮后固定被试 ID、完整人格分数、人口学变量和模拟设置。若 IPIP 响应缺失或身份与 cohort 错配，必须暂停，不得重施校标问卷或换 cohort 补齐。
3. Cohort 与 IPIP 校标只在首轮测量。后续返修轮只测改过的题目新版本；未改且未过主动单题门槛的题复用最近一次完整作答。未改且已过门槛的题，其主测和每个 retest administration 响应都冻结在形成资格的来源快照。逐题按 `subject_id`、`item_id`、`item_version`、`administration` 合并局部新作答与既定来源响应，生成整卷矩阵；不得拼接不同整卷总分、跨版本平均，或让新版本复用旧答案，主测答案也不能充当重测模型输入。不得将局部返修误报成新 cohort 或重复 IPIP 施测。
4. 先提交不可变的测量指标和题目版本快照，再运行控制器判定和返修。控制器元数据可附加在同一测量快照，不得回写或改动该批测量值。旧协议历史不可静默转换为新协议的已完成开发轮。

## 复审与局部返修

1. 将主动单题门槛和 facet 整卷指标作为返修线索，不凭数值臆测题面原因。一般返修仍须有直接、可引用的题文—构念约束依据；例外是四项单题门槛均通过但 facet 整卷指标仍需改善时，按三个单题效度指标最低四分位规则解冻并完成返修，不因缺少直接文本证据而强制暂停。
2. 可按需核查冻结的 facet 定义、高低行为边界、心理骨架、使用背景和蓝图覆盖。材料不完整时暂停，不补造依据。
3. 如进行虚拟内容复审，两位虚拟专家分别盲审题目相关性、完整性、可理解性及目标/非目标构念对齐，指出题面和约束依据；分歧时最多一次虚拟仲裁。六个虚拟认知角色可独立回答并解释题意理解、选项含义和问题片段，不向其提供目标特质、评分键、行为等级或专家结论。
4. 仅当专家或认知证据明确需要时，复用既有情境探测、盲态相邻差异编码等辅助诊断；不得用其单独强制重写。
5. 结构化诊断仅可生成有证据支持的 `repair/replace/defer` 及互不重叠的原子任务。普通文字返修最多四项任务，只改授权的情境或选项文字；目标 facet、behavioral level、计分键、心理骨架、激活机制、行为证据、构念和模拟设定保持不变。固定设计需变更时生成同一蓝图槽位的新版本/候选，并保存替代关系。
6. 每个 facet 每个开发轮的返修提交与复测次数不设上限。只允许编辑仍失败、未接受的 facet；一旦 facet 达标并被接受，其快照和题目版本在该轮剩余时间内锁定，不再修改。若四项单题门槛均通过但 facet 整卷指标仍需改善，按目标 IPIP Hedges' g、目标 IPIP Spearman ρ、Δmin 三项中任一指标排名低于第 25 百分位，解冻该题并完整返修；建立新题目版本并记录修改。不得仅因该题缺少直接文本证据而暂停。未通过单题门槛题既有的 defer/同槽位替代规则仍适用。
7. 每次逻辑失败调用最多 5 次尝试（含首次）；底层 SDK/HTTP 重试计入该次尝试，不增加预算。未耗尽时保留归档并按有限预算重试；五次耗尽时按已确认机制为获准的失败 facet 同槽位补题。失败或 `defer` 候选的同槽位替代额度为永久无限，但每个替代候选仍必须通过完整的材料核查、内容审题和结构校验；若无法安全生成或校验替代题则暂停。不得仅因合格解冻题缺少直接文本证据而暂停；其他明确 `defer` 或证据不可用情形仍按原安全规则处置。未过单题门槛题按同槽位替代规则处理。
8. 局部返修次数不设上限；不得因返修次数本身暂停或将当前开发轮判为耗尽。结构校验失败、服务超时或必需指标不可估计须保留原始证据并按单次逻辑调用的有限预算处理；尝试耗尽后继续使用无限同槽位替代额度，但替代题不得绕过质量门槛。不得伪装成 defer 或擅自改题。

## 开发轮、次数与完成条件

- 固定三个最多可完成的开发轮：开发轮 1 是基线；开发轮 2–3 是最多两个返修轮。只有所有 facet 在同一轮都满足后续成功轮条件时，该轮才完成。Facet 各自的暂存接受状态不能使未完成的整卷开发轮提前记为完成。
- 每个后续成功轮，各 facet 的 α 与 ICC 均须 `≥ .70`；目标 `g`、目标 `rho_s`、`Δmin` 分别相对上一完成轮的原始数值严格增加（未舍入差值 `> 1e-12`，不可用展示舍入值判定）。新比较键为 `target_rho_improvement_gate` 和 `discriminant_delta_improvement_gate`；旧键 `target_rho_noninferiority_gate`、`discriminant_delta_non_decrease_gate` 仅为读取旧历史兼容，不是新协议判据。报告应显示观测到的实际升幅。
- 每 facet 每外层开发轮局部提交并复测不设上限。每次逻辑失败调用最多 5 次尝试（含首次），底层 SDK/HTTP 重试计入该次尝试，不叠加；重启/恢复不重置已用次数。次数是每次逻辑失败调用的预算，不是整个流程总调用数。同槽位替代额度永久无限；不得因平台期或连续未改善而提前停止。
- 状态记录于 `state["facet_iteration_state"]`，核心 schema 包括：`policy_version`、`status`、`development_round`（1–3）、`development_round_batch`（每个开发轮从 1 起计，内部字段）、`completed_rounds`、`local_attempts`、`accepted_facets`（整卷快照）、`failed_facet_ids`、`baseline_facets`、`measurement_batch`、`paused_reason`。完成历史、比较明细、首轮 cohort/IPIP 引用和解冻版本记录可作为附加字段。
- `psychometric_analysis_round` / `measurement_batch` 保留全局测量批次标识；`development_round_batch` 是轮内批序号，每个新开发轮重置为 1。测量快照保留这些内部字段和 `round_completed`、完整 `facet_iteration_state`，但对外报告只展示“第X轮”，不得展示批次数。旧历史不得静默算作新协议已完成轮；只在 `status=complete` 且 `completed_rounds=3` 时允许最终整卷交付。
- facet 整卷达标但仍有题未通过四项主动单题门槛时，可在满足上述最终控制器完成条件后作为 `facet_form_retained` 交付，且 `retention_basis="three_successful_facet_rounds"`、`monitoring_pass=false`。此类题不得标为 `qualified_locked`，不得计入 `frozen_qualified`；报告须将整卷达标与单题门槛失败分开，并标为探索性开发证据。

## COSMIN 证据、版本与恢复

相关性应连接冻结的构念、目标人群和使用背景；完整性应连接计划的 facet 与槽位覆盖；可理解性应分别记录专家判断和认知角色证据。上述证据约束返修理由和修改范围，不与统计门槛合成所谓 COSMIN 认证分数。

每条审查/返修证据绑定实际审查的 `reviewed_item_id` 与 `reviewed_item_version`。改版候选先标记待测状态，并保存来源测量批次、候选 ID/版本和归档路径。若最终版本没有再次接受理解度复核，`post_edit_comprehensibility` 应保持 `not_reassessed`，不得挪用上一版本的审查记录。

- `psychometric_iteration_history` 和 `iteration_metrics_round_XX.json` 保存测量批次标签、开发轮元数据、题文及版本、四项主动门槛、三项 profile 诊断、五项整卷指标、是否入选整卷、原始统计引用、控制器判定、作答数据引用及处置状态。测量数值核心不可被同轮后续步骤覆盖。
- `virtual_content_review_history` 保存来源测量批次、所审题目及版本、虚拟专家/仲裁、认知角色、综合诊断、门禁记录、是否提交、候选 ID/版本与归档路径。
- `item_content_evidence` 保存每个当前题目的审查版本、测量版本、来源批次和改后理解度复核状态。
- 原始模型输出、校验结果、提示词、模型元数据、调用尝试和暂停原因应逐步归档。用户显式恢复时复用已完成步骤，只继续未完成步骤；不得重置局部或调用尝试数，也不得静默把旧 `psychometric_analysis_round` 解释为新开发轮。
- 旧 `scenario_detection_first_v1` 检查点继续使用旧流程；协议、题文、冻结材料、角色或模型配置改变时，不得静默复用归档。

## 验证范围

离线 mock 验证可覆盖首轮基线、两次后续成功返修轮、三个完成轮总数、轮内批次从 1 重置、主动门槛与诊断字段分离、严格升幅、alpha/ICC 边界、无上限局部返修、接受 facet 锁定、恢复预算、版本化解冻、原子发布、暂停状态和 `facet_form_retained` 处置。代码修改不授权自动启动真实模型试验、恢复历史采样任务、增加样本量或调用预算。不进行哈希验证或视觉 QA。
